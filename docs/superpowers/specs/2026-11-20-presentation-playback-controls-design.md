# 展示播放控制调整设计

日期：2026-11-20

## 目标

将主控台右下角按钮从左到右调整为：**开启展示、结束展示、上一套、开始/暂停、下一套**。每套播放方案相当于一页幻灯片，切换方案时只播放该方案自己的画面队列和音频列表。

## 方案与范围

沿用现有 `PlaybackWindow`、`PlaybackCoordinator` 和 `PlaybackQueue`，只扩展正式输出控制，不重建状态机，不改变预览、素材、方案编辑或持久化模型。

预计修改：

- `src/AVPC/MainWindow.xaml`：五个正式输出按钮及状态文字。
- `src/AVPC/MainWindow.xaml.cs`：开启、结束、前后切换、暂停/恢复的事件处理与按钮状态。
- `src/AVPC/Services/PlaybackCoordinator.cs`：正式画面、音频和计时的暂停/恢复。
- `src/AVPC/PlaybackWindow.xaml.cs`：暂停/恢复正在执行的淡出动画。
- `src/AVPC.Core/PlaybackQueue.cs` 与对应测试：增加上一套导航。

## 行为契约

### 开启展示

- 只创建或显示全屏黑色展示窗口，不加载方案、不播放媒体，也不停止当前预览。
- 此时“开始/暂停”处于可开始状态，上一套、下一套和结束展示仅作用于正式输出。

### 开始/暂停

- 展示窗口已打开且没有当前方案时，验证方案并从第一套开始，停止预览。
- 正在播放时暂停；暂停时恢复。
- 暂停必须同时冻结当前视频、独立音频、图片停留计时、视频结束检测和已经开始的淡出动画。
- 恢复时从原媒体位置和原剩余图片停留时间继续，不重新开始当前方案，也不重置整套音频列表。
- 按钮按状态显示开始、暂停或继续；暂停不改变当前方案索引。

### 上一套与下一套

- 有当前方案时，上一套/下一套立即切换并从头播放目标方案自己的画面和音频。
- 即使当前处于暂停状态，手动切换方案后目标方案也直接开始播放。
- 第一套点击上一套不操作。
- 没有当前方案时，下一套从第一套开始。
- 最后一套之后再次点击下一套，沿用现有结束规则：停止媒体和队列、展示窗口保留黑屏；再次开始回到第一套。
- 素材自然结束仍不自动切换方案。

### 结束展示

- 停止当前画面、音频、计时和淡出，复位正式输出状态并关闭展示窗口。
- 主控台保持运行；下次开启展示重新创建黑屏窗口。
- 结束展示后，预览状态不被意外修改。

1. 先为 `PlaybackQueue` 的上一套、第一套边界和停止后重开始编写失败测试，再做最少实现。
2. 运行 `dotnet test AVPC.sln`，全部通过。
3. 运行 `dotnet build AVPC.sln`，0 错误且无本次新增警告。
4. 运行 `dotnet build src/AVPC/AVPC.csproj`，更新 `start.cmd` 实际使用的输出。
5. 由用户手动验证五按钮顺序、只开黑屏、逐套前后切换、暂停/恢复图片与音视频、最后一套停止、结束展示关闭窗口，以及物理双屏和声音效果；未实际验证的项目必须明确列出。
