# 中间预览时间轴与双媒体队列设计

日期：2026-11-20

## 目标

重做中间方案浏览区域，用统一的画面时间轴和两排相同样式的媒体卡片完成预览、删除和排序，并把两个循环开关合并为一个“循环播放”。

本设计在现有混合画面队列之上迭代，不改变逐套手动正式播放、预览与正式输出隔离、媒体等比显示和自动保存契约。

## 已确认的视觉方向

采用用户选择的 C「演播室 · 明亮极简面板」：

- 中间区域使用浅色工作台、白色卡片、细分隔线和绿色状态强调。
- 左右素材库和方案列表保持现有深色 Mica 风格，不做无关重设计。
- 上方为实际输出效果预览，下方为播放按钮、总进度条、当前时间和总时长。
- “画面播放队列”和“音频播放列表”上下排列，使用相同的缩略图、序号、名称、时长、删除按钮和拖拽手柄。
- 当前画面项使用绿色描边；音频选中只显示选中状态，不改变预览声音。

## 画面统一时间轴

### 时长与位置

画面时间轴只计算当前方案的 `Visuals`，不包含独立音频时长。

- 视频项时长取导入时读取并持久化的媒体时长。
- 图片项时长取当前方案的 `ImageDurationSeconds`。
- 总时长为所有画面项时长之和。
- 示例：视频 1 分钟、图片 5 秒、视频 3 分钟、图片 5 秒，总时长为 4 分 10 秒。
- 每项有全局起点和终点。上述第 2 张图片的起点为 1 分 00 秒，终点为 1 分 05 秒。

核心时间轴放在 `AVPC.Core`，提供总时长、按索引取得结束点、当前项本地位置到全局位置的换算，以及全局位置到素材项和本地位置的换算。不得依赖 `DispatcherTimer`、`MediaPlayer` 或 XAML。

### 播放与点击定位

- 正常预览时，进度条跨越图片和视频连续推进，不再在每项切换时归零。
- 点击画面卡片后暂停预览，显示该素材的结束画面，总进度停在该素材的全局终点。
- 图片直接保持显示；视频定位到末尾附近的可显示帧，界面时间仍显示该项终点，避免媒体结束事件立刻推进下一项。
- 在定位暂停状态再次播放时，从下一项开始；若已经是末项，开启循环则回到首项，未开启循环则保持结束状态。
- 现有进度条保留 seeking 能力，并改为按整条画面时间轴定位到对应素材和本地位置。
- 点击定位只改变预览，不改变正式播放方案索引或输出窗口。

### 元数据

- `MediaAsset` 增加可往返序列化的媒体时长，导入视频和音频时记录时长。
- 加载旧工作区时，用重新读取的媒体属性按路径补齐素材库及方案内素材的时长。
- 文件不可用时仍保留素材和方案记录，并沿用现有不可用标记。
- 视频时长尚未知时，不伪造精确总时长；界面显示未知状态，媒体元数据就绪后刷新时间轴。

## 画面播放队列

- 保留横向单行排列和超出宽度后的横向滚动。
- 每项显示序号、缩略图、文件名和该项时长。
- 点击卡片按上述规则定位到该项结束点。
- 点击右上角 `×` 只从当前方案的画面队列删除该项，不从素材库删除文件或素材记录。
- 长按后拖拽排序；鼠标沿用列表控件支持的等价拖拽操作。
- 排序后序号立即更新，并同步修改 `PlaybackScheme.Visuals` 的实际顺序。
- 末尾保留虚线“追加画面”拖放框，只接受图片和视频。
- 核心集合提供按索引删除和移动操作，并维持只包含图片、视频的约束。

## 音频播放列表

- 位于画面播放队列下方，视觉样式和卡片尺寸与画面项一致。
- 音频缩略图使用现有 `Assets/audio.png`，显示序号、文件名和时长。
- 点击音频卡片只选中，不开始、暂停或切换任何预览音频。
- 右上角 `×` 只从当前方案的音频列表删除该项。
- 长按拖拽排序，排序结果同步到 `PlaybackScheme.Audios`，决定顺序播放次序。
- 末尾保留虚线“追加音频”拖放框，只接受音频。
- 保留右侧方案卡片的现有音频摘要和删除入口，并始终反映同一音频列表。

## 统一循环与声音

- 删除“画面循环”和“音频循环”两个选项，在中间双队列区域只保留一个“循环播放”。
- `PlaybackScheme` 使用统一的 `IsLooping`。
- 开启后，画面队列到达末尾从头继续；独立音频列表到达末尾也从头继续。
- 两个队列仍各自按自身时长推进，统一循环不意味着二者时长相同或互相等待。
- 未开启时，两个队列各自播完停止，沿用现有末项视频保持最后一帧或淡出行为。
- 当前方案没有独立音频时，视频使用原声。
- 当前方案只要包含至少一个独立音频，所有视频均静音；即使独立音频已经播放结束，也不恢复视频原声。
- 预览和正式输出采用相同规则。

## 编辑、预览与保存

- 删除、排序、追加和循环设置后立即刷新对应 `SchemeCardViewModel` 并安排自动保存。
- 修改正在预览的方案时，预览从修改后的队列开头重新开始，避免旧播放索引、定时器或时间轴错位。
- 正式输出期间沿用现有 `EnsureEditable` 限制，不允许并发编辑破坏输出状态。
- 预览与正式输出仍相互隔离；开始正式播放时停止预览。

## 持久化与迁移

- 工作区保存统一 `IsLooping`、画面和音频实际顺序，以及素材时长。
- 新格式 JSON 往返后恢复所有 get-only 集合、时长和循环状态。
- 读取旧工作区时兼容 `IsVideoLooping`、`IsVisualLooping` 和 `IsAudioLooping`。
- 旧数据中 `IsVideoLooping`、`IsVisualLooping`、`IsAudioLooping` 任意一个为开启时，迁移后的 `IsLooping` 为开启；旧图片组原有的默认画面循环行为继续保留，因此也会开启统一循环。
- 新保存不再写出两个独立循环选项。

## 错误与边界

- 空画面队列沿用现有方案校验和空状态，不创建核心时间轴播放实例。
- 删除最后一项后，总时长归零并显示空队列提示。
- 删除或排序不改变素材库文件，不静默清理丢失素材。
- 向画面拖放框加入音频或向音频拖放框加入图片、视频时，不改变队列并显示简短提示。
- 视频时长为 0 时继续遵守现有淡出约束，不提前触发淡出。

## 验证

先编写并运行失败测试，再写最少实现使其通过：

1. 示例混合队列总时长为 4 分 10 秒，第 2 张图片终点为 1 分 05 秒。
2. 当前项本地播放位置能换算为连续全局进度，全局位置能映射回正确素材。
3. 画面和音频都能删除、移动并维持正确顺序和类型约束。
4. 统一循环同时驱动 `VisualPlaylist` 与 `AudioPlaylist`。
5. 无独立音频时视频不静音，有任意独立音频时视频静音。
6. 新 JSON 保留统一循环、双队列顺序和素材时长，旧 JSON 正确迁移。

dotnet build AVPC.sln
dotnet build src/AVPC/AVPC.csproj
