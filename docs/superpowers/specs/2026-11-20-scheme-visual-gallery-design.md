# 方案浏览与混合媒体长廊设计

## 背景

当前主控台通过「画面来源」「视频」和图片多选列表配置方案，每套方案只能选择一个视频或一组图片。此次调整把画面配置改为按顺序排列的混合媒体队列，并将主要编辑入口移到右侧方案卡片和中间媒体长廊。

## 已确认的决策

- 采用中间「选中方案设置」区域的横向媒体长廊，不在右侧卡片中展开图片列表。
- 图片和视频进入同一个有序队列。
- 图片停留指定秒数后切换；视频完整播放一次后切换。
- 开启画面循环时，整个图片和视频队列从头循环。
- 拖到中间虚线框的素材追加到队列末尾。
- 拖到右侧方案缩略图的素材替换整个画面队列，并成为队列第一项和方案封面。
- 方案只使用已经分配给它的素材，不从素材库自动读取或补入其他视频、图片、音频。

## 界面与交互

### 中间设置区域

移除以下控件：

- 「方案名称」文本框。
- 「画面来源」选择器。
- 「视频」选择器。
- 原先从素材库读取全部图片的多选列表。
- 原先从素材库读取全部音频的多选列表。

新增「画面播放队列」横向长廊：

- 每个条目显示素材缩略图、文件名和顺序。
- 图片与视频按实际播放顺序排列。
- 内容超出可用宽度时横向滚动，不自动换行。
- 末尾固定提供虚线拖放框，提示「拖拽图片、视频到这里，追加到结尾」。
- 虚线框只接受图片和视频；拖入音频时提示改用方案音频区域。
- 保留「每张图片停留（秒）」设置。
- 独立音频区域只展示当前方案已经添加的音频，不列出素材库中的其他音频。

本迭代只支持追加和整队替换，不新增队列内拖拽排序或单项删除功能。

### 右侧方案卡片

- 方案名称保留在卡片上，双击后进入行内重命名。
- Enter 或失去焦点保存名称，Esc 取消编辑。
- 卡片缩略图显示画面队列第一项的素材缩略图。
- 将图片或视频拖到缩略图时，清空原画面队列，再把该素材作为第一项。
- 将音频拖到方案卡片时，仍只追加到该方案的独立音频列表，不改变画面队列。
- 卡片摘要按实际内容显示图片数和视频数。
- 修改队列、名称或音频后立即刷新对应 `SchemeCardViewModel`，并安排工作区保存。

## 核心模型

`PlaybackScheme` 以统一的 `Visuals` 有序集合作为唯一画面来源：

- 集合元素为 `MediaAsset`，只允许 `Image` 和 `Video` 两种类型。
- 每个方案持有自己的素材对象和顺序，不通过素材库列表推断方案内容。
- 追加时按路径忽略重复素材，沿用当前方案去重行为。
- `IsVideoLooping` 的界面语义改为 `IsVisualLooping`，控制整个画面队列。
- `Audios`、`IsAudioLooping`、`ImageDurationSeconds` 和 `VideoEndBehavior` 保持独立。

核心队列状态不依赖 WinUI、`DispatcherTimer` 或 `MediaPlayer`，至少提供当前项和下一项推进能力。非循环队列到达末尾时返回结束状态，不自动回到第一项。

## 播放流程

### 图片

- 显示当前图片并启动停留计时。
- 计时结束后推进到下一项。
- 非循环队列以图片结束时，保留最后一张图片。

### 视频

- 播放当前视频；存在独立音频时，视频原声保持静音。
- 非末尾视频播放结束后直接推进，不执行保持最后一帧或结束淡出。
- 非循环队列以视频结束时，沿用现有结束行为：保持最后一帧，或在有效的媒体时长就绪后执行最后 2 秒淡出到黑屏。
- 媒体时长为 0 时不得提前触发淡出。

### 循环与音频

- 画面循环只控制 `Visuals` 队列，不改变音频循环。
- 音频循环只控制当前方案的 `Audios` 列表，不改变画面队列。
- 预览和正式输出使用相同的核心顺序与结束规则。
- 素材自然结束只推进当前方案内的画面队列，不自动切换到下一套方案。

## 持久化与迁移

- 新工作区保存 `Visuals` 的完整素材信息和顺序，并保存新的画面循环字段。
- 保存内容不包含素材库中未分配给方案的视频、图片或音频。
- 反序列化旧工作区时：
  - 旧方案含视频时，将该视频转换为唯一画面项。
  - 旧方案含图片组时，按原顺序转换为画面项。
  - 保留名称、音频列表、图片停留时长、循环和结束行为。
- 新格式往返后必须恢复 `Visuals` 和 `Audios` 等 get-only 集合。
- 素材文件丢失时保留方案记录，并按现有规则标记不可用，不静默删除队列项或方案。

## 错误处理

- 画面队列为空时，方案校验提示需要拖入视频或图片。
- 向虚线框拖入不支持的类型时，不改变队列，并显示简短提示。
- 文件路径无法匹配素材库中已导入的素材时，不创建未经验证的新素材记录。
- 正式输出期间继续沿用现有编辑限制，停止输出后再修改方案结构。

## 测试与验收

先编写或更新核心失败测试，再实现功能：

1. 图片和视频追加后保持拖入顺序，重复路径不重复添加。
2. 拖到缩略图的替换操作清空旧队列，只保留新素材。
3. 混合队列按图片、视频、图片的顺序推进。
4. 循环队列从末项回到首项；非循环队列在末项结束。
5. 画面队列推进不改变音频列表及其循环设置。
6. 旧 JSON 中的视频方案和图片组方案都能迁移。
7. 新 JSON 往返后保留混合顺序、音频、循环、停留时长和结束行为。
8. 方案校验拒绝空队列和音频混入画面队列的情况。

完成后实际运行：

```powershell
dotnet test AVPC.sln
dotnet build AVPC.sln
dotnet build src/AVPC/AVPC.csproj
```

界面验收包括双击重命名、缩略图替换、虚线框追加、横向滚动、封面与卡片刷新，以及预览和正式输出中的混合顺序、循环和结束行为。物理双屏、声音或视觉效果若未实际验证，必须在交付说明中明确列出。
