# 方案管理、手动导航与展示关闭设计

## 目标

- 将方案删除入口移到方案卡片右上角，并增加二次确认。
- 修正上一套、下一套的首尾循环和全黑结束状态切换。
- 手动切换方案后只定位并准备播放，不自动开始。
- 让“结束展示”每次点击都能立即关闭展示区，不再偶发失败。
- 将预览播放器下方的音量滑条移到底部倍速与“开启展示”之间，不改变全局音量逻辑。

## 方案卡片删除

移除方案列表下方的“删除选中方案”按钮。在卡片右上角、三角形播放按钮左侧增加垃圾桶按钮。

点击垃圾桶后显示 `ContentDialog`，明确包含方案名称、“删除后无法撤销”的提示，以及“删除”和“取消”两个操作。只有选择“删除”才移除方案；取消时保持方案、选中状态和预览状态不变。

正式输出正在播放时仍禁止修改方案结构。若输出窗口仅处于已定位或暂停状态，删除当前方案前先执行与结束展示相同的停止和隐藏流程，避免输出协调器继续引用已删除方案。

## 播放队列状态

`PlaybackQueue` 明确区分“当前选择”和“是否正在播放”，并记录是否已经越过最后一套进入全黑结束状态。

状态规则：

| 状态 | 当前索引 | 正在播放 | 全黑结束状态 |
| --- | --- | --- | --- |
| 尚未开始 | 无 | 否 | 否 |
| 已定位、等待开始 | 有 | 否 | 否 |
| 正在播放或暂停 | 有 | 是 | 否 |
| 最后一套之后的全黑状态 | 无 | 否 | 是 |

行为规则：

- 点击“下一套”从当前方案定位到下一套并把播放状态改为否。
- 最后一套点击“下一套”进入全黑结束状态并返回空方案。
- 全黑结束状态点击“上一套”回到最后一套，保持等待开始状态。
- 第一套点击“上一套”跳到最后一套，保持等待开始状态。
- 其他位置点击“上一套”定位到前一套，保持等待开始状态。
- 已定位时点击“开始”播放当前方案；尚未开始且已有方案时从第一套开始。
- 点击方案卡片上的播放按钮仍直接选择并开始该方案。
- “结束展示”或重新建立队列后回到尚未开始状态。

## 预定位播放

`PlaybackCoordinator` 增加预定位能力：加载方案的第一项画面，建立独立音频和淡出计时所需状态，但不调用媒体播放。上一套或下一套只调用预定位，不自动开始媒体。

从预定位状态点击“开始”时，从当前方案的第一项开始播放。视频从零点开始，图片开始停留计时，独立音频从第一首开始。该过程不改变已有暂停/继续语义。

## 结束展示生命周期

当前实现先停止媒体，再同步调用 `Window.Close()`。诊断日志和 Windows 事件记录显示该调用偶发返回 `COMException 0x80004004`，窗口已停止但未隐藏，因此画面全黑且需要再次点击。

结束展示改为：

1. 停止队列和播放协调器，释放媒体并清空输出内容。
2. 使用 `AppWindow.Hide()` 隐藏展示窗口。
3. 保留窗口和协调器对象，下次“开启展示”时重新全屏并激活。

不再使用 `Window.Close()` 作为结束展示的常规路径。订阅输出窗口的关闭事件；只有用户通过系统方式真正关闭窗口时，才清空主窗口持有的窗口和协调器引用。

输出模式文字和按钮状态以 `AppWindow.IsVisible` 判断展示窗口是否可见。输出窗口隐藏时切换显示器只记录选择，不得意外重新显示窗口。

## 全局音量条

将现有 `PreviewVolume` 滑条从预览播放器控制行移动到底部工具栏，位于倍速选择器和“开启展示”之间。扬声器图标保留在预览播放器控制行，不创建第二套音量状态。

滑条继续使用原名、现有值变更处理器和现有全局音量同步逻辑。

## 测试

- 核心测试覆盖下一套顺序、最后一套进入全黑、全黑后上一套恢复最后一套、第一套上一套循环到最后一套。
- 核心测试覆盖导航只改变选择而不把播放状态设为正在播放。
- 核心测试覆盖显式开始当前定位方案和从尚未开始状态开始第一套。
- 现有方案移动、选择、停止、持久化和视觉队列测试必须继续通过。
- 删除确认、窗口隐藏复用、全屏恢复和音量条位置属于 WinUI 交互，构建通过后由用户手动验证。

## 验收标准

- 底部不再出现“删除选中方案”。
- 每个方案播放三角形左侧有垃圾桶按钮，取消确认时不删除，确认后立即删除。
- 上一套或下一套切换后不自动播放，按钮显示“开始”。
- 第一套点击上一套到末套；末套点击下一套进入全黑；全黑点击上一套回到末套并等待开始。
- 点击一次“结束展示”后输出窗口立即消失，不显示错误提示。
- 再次开启展示可复用隐藏窗口并正常全屏输出。
- 音量滑条位于倍速与“开启展示”之间，扬声器图标仍在预览区，音量调节行为不变。
